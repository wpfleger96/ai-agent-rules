# Target: Concept

An idea or domain the user wants to reason with: an algorithm, a design pattern, a distributed-systems property, a field of knowledge (for example consensus, CRDTs, spaced repetition, tax-advantaged accounts).

## Frame prompts

The user's model should cover: the mechanism, the variables that matter, and where it applies. Question ideas if they are stuck:

- What is the mechanism, step by step?
- Which variable or assumption, if changed, breaks it?
- What is it commonly confused with, and how do they differ?
- Where does it apply in the user's own work?

## Artifacts (Step 2)

1. The mechanism, stated as a causal chain, with sources.
2. Key variables and assumptions, and what happens when each is violated.
3. One worked concrete example, traced step by step.
4. Tradeoffs and the main alternatives.
5. Common misconceptions.
6. Evidence strength, where the concept rests on empirical claims: what is well established, what is contested, with links.

## Review-question targets

Mechanism, assumptions and their failure, distinctions from similar concepts, application to the user's own context. Prefer "why" and "what happens if" questions over definitions.
